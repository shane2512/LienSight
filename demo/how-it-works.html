How Liensight
works.

A public record, a network that has to agree on it, and a token that won't move until someone has looked.

1

Every node reads ACRIS

A cron-triggered Chainlink CRE workflow has each node query NYC ACRIS for one property: legal records for the borough, block and lot, then the document type of each filing.

2

The network agrees

Each node sorts and de-duplicates the filings into the same canonical list. The workflow uses identical-consensus aggregation, so nothing is written unless the nodes agree byte for byte.

3

The token reacts

The signed report reaches the token through Chainlink's forwarder. A new adverse filing sets restricted = true and stores a hash of the cited documents.

What counts

Adverse filings, checked against the official codes

Every code below was verified against the ACRIS Document Control Codes dataset (7isb-wh4c). The map is versioned, and its hash is stored on the token, so anyone can check which rules it was deployed with.

The contract

A token that only listens to the right workflow

The forwarder is shared by every CRE workflow, so the token checks who sent each report before it acts.

  • Workflow owner check. Reports from any other workflow owner revert.
  • Property check. Reports for any other property key revert.
  • Seen filings stay seen. A lien the issuer already cleared never re-restricts on an unrelated new filing.
  • Reviewed clears only. clearRestriction(citedHash, reason) reverts if a new lien landed after the issuer's review.
  • Discharges only suggest. A release emits ClearSuggested; it never clears on its own.
  • Fail static. A failed, truncated or empty ACRIS response writes nothing.
Honest limits

What Liensight is not

  • Not title. The token is equity in an SPV that owns the property. The restriction is issuer-governed under the operating agreement, not a statutory duty.
  • Not a title search. ACRIS lags real events by days, and has no lis pendens or foreclosure type. Liensight is an early-warning signal.
  • Not yet on a live DON. Reports were written with cre workflow simulate --broadcast and Chainlink's mock forwarder, which uses a public placeholder workflow owner. Production would use a deployed workflow and the KeystoneForwarder.
  • One source today. Consensus is over a single public API. A second source (NYC Department of Finance) is the next step.
