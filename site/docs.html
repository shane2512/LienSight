Liensight docs.

Liensight restricts a real-estate token’s transfers when a lien is recorded against the building. A Chainlink CRE workflow reads New York City’s public land records (ACRIS), the nodes agree on what they say, and a signed report tells the token on-chain. This page covers how to run it, how it works, and where it stops.

Getting started

Quickstart

From a fresh clone to passing tests and a live workflow simulation against real NYC records in about ten minutes. You don’t need a wallet or any keys for this.

Prerequisites

ToolVersion usedGet it
Foundry (forge, cast)1.5.1getfoundry.sh, then foundryup
Node.js and npm20 or newernodejs.org
Chainlink CRE CLI (cre)v1.2.0docs.chain.link/cre
Gitanygit-scm.com
  1. Clone, with submodules

    The contracts pull OpenZeppelin (and forge-std through it) as git submodules.

    bash
    git clone --recursive https://github.com/shane2512/LienSight.git liensight
cd liensight
  2. Install the workflow’s packages

    This also installs Bun locally, which the CRE CLI uses to build the TypeScript workflow.

    bash
    cd workflow && npm i && cd ..
  3. Run all 35 tests
    bash
    cd contracts && forge test && cd ..   # 18 passed
cd workflow && npm test && cd ..      # 17 passed (3 files)
  4. Simulate the workflow against live ACRIS

    Log in once, put the local Bun on your PATH, and simulate both configured properties.

    bash
    cre login
export PATH="$PWD/workflow/node_modules/.bin:$PATH"

# Bronx 2-5789-1022: has a recorded lien of common charges
cre workflow simulate ./workflow -T staging-settings --non-interactive --trigger-index 0

# Manhattan 1-905-1347: nothing adverse
cre workflow simulate ./workflow -T clean-settings --non-interactive --trigger-index 0

    Expect ACRIS docs=14 adverse=2026092900833001:LOCC for the Bronx lot and ACRIS docs=12 adverse=none for Manhattan. Counts can grow as the city records new filings.

    i

    Without --broadcast the write is a dry run and logs a zero transaction hash. That’s expected. On Windows PowerShell, set the path with $env:Path = "$PWD\workflow\node_modules\.bin;$env:Path".

  5. Read the result on-chain

    The same workflow, run with --broadcast, already restricted the demo token.

    bash
    cast call 0xf813c584Fe5e8c86A3F6c7265923CeE0850604aE "restricted()(bool)" \
  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
# true

Verify the live deployment

Every claim about the Sepolia token can be checked independently. Steps 1–3 need nothing but a browser.

  1. See the lien in the public record

    Open Check a lot and click Bronx 2-5789-1022 · has a lien. The page reads ACRIS live and shows one adverse filing: LOCC 2026092900833001, recorded 2026-09-30.

  2. See the report on-chain

    Open the token’s events on Etherscan. The report(...) call carries the document-set hash the nodes agreed on (0xde6f…3948).

  3. See the restriction

    Open Proof, which reads restricted() from Sepolia in your browser.

  4. Ask the chain directly (needs Foundry)
    bash
    RPC=https://ethereum-sepolia-rpc.publicnode.com
TOKEN=0xf813c584Fe5e8c86A3F6c7265923CeE0850604aE
cast call $TOKEN "restricted()(bool)" --rpc-url $RPC        # true
cast call $TOKEN "citedHash()(bytes32)" --rpc-url $RPC      # 0xb87dc80e…49f4
cast call $TOKEN "reportReceiver()(address)" --rpc-url $RPC # 0x15fC6ae9…9F88 (CRE forwarder)
# even the issuer can't move shares: reverts with TransferRestricted() (0xe827105e)
cast call $TOKEN "transfer(address,uint256)(bool)" 0x000000000000000000000000000000000000dEaD 1 \
  --from 0xd51E7130B55f10595939f274cCB8c00b52C915b4 --rpc-url $RPC

    citedHash equals keccak256(abi.encode([bytes32(2026092900833001)])), so the restriction provably cites that ACRIS document.

Concepts

Architecture

Three parts: a public data source, a Chainlink CRE workflow, and a token contract. The workflow carries facts from the first to the third, and nothing else can set the token’s restriction.

ComponentRole
ACRIS on NYC Open DataThe city’s land records. Legals (8h5j-fqxa) maps a lot to document IDs; Master (bnx9-e6tj) gives each document’s type.
CRE workflowRuns on every node of a Chainlink DON on a schedule. Fetches, agrees, signs and writes.
Chainlink forwarderVerifies the DON’s signatures and calls the receiver contract with the report and metadata.
LiensightTokenERC-20 SPV share token. Restricts transfers on a new adverse filing; only the issuer can clear.
Issuer multisigHolds the supply, reviews restrictions, and clears them publicly.
WebsiteExplains, checks lots and reads state. Not part of the trust path.

Design decisions

DecisionWhy
A DON for one public APINo single server or operator decides what the chain sees, and the restriction cites a document anyone can look up.
Identical consensus, not medianThe output is a set of documents, not a number. Byte-identical canonical JSON makes agreement exact.
Fail closedA truncated or empty answer is more likely an outage or a wrong lot than a clean property, so nothing is written.
Restrict automatically, clear by a personA lien appearing is a fact. Whether it still matters (paid, disputed, bonded) is a judgment, made publicly by an accountable issuer.
Discharges only suggest a clearA release can be partial or for another lien, so ClearSuggested flags it instead of lifting the restriction.
Cleared liens never re-restrictseenAdverse remembers every reported document; only a genuinely new lien restricts again.
SPV equity, not titleThe token represents shares in a holding company. Liensight signals risk; it doesn’t settle ownership.
Concepts

Why Chainlink CRE

A lien lives in a government database, and a smart contract can’t call an API. Closing that gap takes three things a contract can’t do alone, and CRE provides each one:

ReadHTTP capability

Every node queries NYC Open Data directly and independently.

AgreeIdentical consensus

consensusIdenticalAggregation: one differing node means no report.

ActSigned EVM write

runtime.report signs; EVMClient.writeReport delivers via the forwarder.

The workflow is TypeScript on @chainlink/cre-sdk, compiled to WebAssembly by the CRE CLI. Its whole entry point is workflow/workflow.ts, 73 lines.

Concepts

How the workflow runs

One run, for one property, every ten minutes:

  1. Trigger

    CronCapability fires on "0 */10 * * * *".

  2. Fetch the lot’s documents

    Each node asks ACRIS Legals for every document ID on the BBL, then asks Master for their types, 80 IDs per request so URLs stay short.

  3. Fail closed

    A non-200 response, a response that hits the 5,000-row limit, or zero documents throws. No report is written.

  4. Canonicalize

    Keep documents present in both datasets, dedupe, sort by ID, and serialize to JSON, so every honest node produces identical bytes.

  5. Reach consensus

    consensusIdenticalAggregation<string>() requires all nodes to return the same string.

  6. Classify and encode

    The adverse map splits documents into adverse and discharge IDs; the report carries the property key, the document-set hash and both ID lists.

  7. Sign and write

    runtime.report signs it, and EVMClient.writeReport sends it through the forwarder to LiensightToken.onReport. The run logs report written tx=….

Concepts

The adverse map

Which ACRIS document types count is a policy, kept in workflow/src/codeMap.json (version 1) and verified against ACRIS Document Control Codes (dataset 7isb-wh4c). Its hash is fixed in the token at deploy time, so any change is visible.

Adverse · restricts

FL federal lien (IRS) · FTL federal lien, other · NTXL notice of estate tax lien · TLS tax lien sale certificate · LOCC lien of common charges · JUDG judgment

Discharge · suggests a clear

RFL · RFTL · DTL · DPFTL · WFL · RTXL · TOLCC · PWFL · PRFL: releases, discharges, withdrawals and terminations of those liens

!

ACRIS has no document type for lis pendens or foreclosure. Those are court and county-clerk filings, so Liensight does not claim to detect them.

Contract reference

LiensightToken is an OpenZeppelin ERC-20 (Solidity 0.8.24) with an issuer-governed transfer restriction. Constructor: (name, symbol, issuerMultisig, reportReceiver, codeMapHash, expectedWorkflowOwner, propertyKey); the full supply of 1,000,000 LSPV is minted to the issuer.

Reference

Report format

The report is ABI-encoded as (bytes32, bytes32, bytes32[], bytes32[]):

FieldContent
propertyKeykeccak256("BBL:2-5789-1022") for the demo property
docSetHashkeccak256 of every documentId:docType on the lot, sorted, joined by newlines
adverseAdverse document IDs as bytes32
dischargeDischarge document IDs as bytes32

Numeric 16-digit ACRIS IDs are left-padded, so 2026092900833001 stays readable on-chain; legacy IDs such as FT_2300000813130 are hashed. The forwarder’s metadata is packed as workflowId (32) | workflowName (10) | workflowOwner (20); the token reads the owner from bytes 42–62.

Guides

Deploy your own token

Deploy a token on Sepolia, point the workflow at it, and send it a real report. You need a funded Sepolia account.

  1. Create a keystore account

    Foundry keeps the key encrypted; nothing goes on the command line.

    bash
    cast wallet import liensight-deployer --interactive
  2. Set the constructor inputs
    bash
    cd contracts
export FORWARDER=0x15fC6ae953E024d975e77382eEeC56A9101f9F88        # CRE simulator forwarder
export WORKFLOW_OWNER=0xaAaAaAaaAaAaAaaAaAAAAAAAAaaaAaAaAaaAaaAa   # simulator placeholder owner
export CODEMAP_HASH=0xf85b55218f5961096bde039896bb3b115179f44c76446ff88e22e3b94326faf3
export ISSUER=<your address>                                        # receives supply, can clear
  3. Deploy

    Sepolia charges far more gas for contract code than Foundry estimates, so keep the multiplier.

    bash
    forge script script/Deploy.s.sol --rpc-url https://ethereum-sepolia-rpc.publicnode.com \
  --account liensight-deployer --broadcast --gas-estimate-multiplier 800
# LiensightToken: 0x…
  4. Point the workflow at it

    Put the printed address in tokenAddress in workflow/config.staging.json.

  5. Broadcast a real report

    Add CRE_ETH_PRIVATE_KEY for a funded Sepolia key to a .env file at the repo root (it is git-ignored; never commit it), then:

    bash
    cre workflow simulate ./workflow -T staging-settings --non-interactive --trigger-index 0 --broadcast
# ... [USER LOG] report written tx=0x…

    Open the hash on Etherscan, then run cast call <token> "restricted()(bool)".

i

For production, deploy the workflow on a CRE DON, then have the issuer call setExpectedWorkflowOwner with the deployed workflow’s owner and use the production forwarder (requires cre account access).

Operations

Limits

  • Testnet only. Reports were written with cre workflow simulate --broadcast through the simulator’s forwarder; consensus ran in the local simulator, not on a live multi-node DON.
  • The demo token trusts the simulator’s placeholder owner, so anyone using that forwarder could report to it. Production rotates to a deployed workflow’s owner.
  • Records lag. ACRIS records filings days after the event: an early warning, not a title search.
  • No lis pendens or foreclosure: ACRIS has no type for them.
  • One source. Every node reads the same public API; a second source is on the roadmap.
  • Not legal advice. It flags public filings; it does not judge their legal effect.

FAQ

Does the token own the building?

No. It represents shares in the company (SPV) that owns the building. The restriction comes from the issuer’s own rules, not from property law.

Why not just run a server that checks ACRIS?

Then that server decides what the chain sees. With CRE, every node reads the record independently and they must agree before anything is written.

Can a lien be removed automatically?

No. A discharge filing emits ClearSuggested; only the issuer clears, publicly, naming the liens it reviewed.

What happens if ACRIS is down?

The workflow fails closed and writes nothing, so the token keeps its last known state.

Does it work outside New York City?

Not yet. Any county with open, queryable land records could be added the same way.

Is any personal data on-chain?

No. Only document IDs, document types and hashes. No party names.

Glossary

ACRISAutomated City Register Information System: New York City’s public record of property documents.
BBLBorough-block-lot: the city’s identifier for a tax lot, for example 2-5789-1022.
CREChainlink Runtime Environment: runs workflows across a decentralized oracle network.
DONDecentralized oracle network: the nodes that run the workflow and reach consensus.
ForwarderThe Chainlink contract that verifies a DON report and calls the receiver.
SPVSpecial-purpose vehicle: the company that owns the building; the token is its shares.
LOCCLien of common charges: a condominium’s lien for unpaid charges (the demo filing).

citedHashHash of the liens behind the current restriction; the issuer must name it to clear.
