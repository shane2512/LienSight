threat model

Try to break it.

Every attack we know about, the line of defense that stops it, and the test that proves it. Plus the risks that are still open.

ATTACK 01
Spoofed workflow

Another CRE workflow reports to the token.

The forwarder is shared by every workflow. The token reads the workflow owner from the report metadata and rejects anyone else.

test_reportFromWrongWorkflowOwnerReverts
ATTACK 02
Wrong caller

Someone calls onReport directly.

Only the configured forwarder address may deliver reports.

test_onReportFromNonReceiverReverts
ATTACK 03
Wrong building

A report for a different property.

The property key is fixed at deploy time. A report for any other lot reverts.

test_reportForWrongPropertyReverts
ATTACK 04
Garbled metadata

Short or malformed metadata.

Metadata shorter than the forwarder's 62-byte layout reverts before anything is decoded.

test_shortMetadataReverts
ATTACK 05
Blind clear

The issuer clears a lien it never saw.

Lien B lands while the multisig is signing a clear for lien A. The clear names the reviewed set, so it fails.

test_clearWithStaleReviewedHashReverts
ATTACK 06
Zombie lien

A cleared lien re-restricts forever.

Liens already reported are remembered. An unrelated new filing doesn't bring back a lien the issuer already cleared.

test_clearedLienDoesNotRestrictAgainOnUnrelatedFiling
ATTACK 07
Replay

The same report sent twice.

A report with an unchanged document-set hash does nothing.

test_unchangedDocSetHashIsNoOp
ATTACK 08
Gas bomb

So many liens the report runs out of gas.

The token stores one hash of the cited liens, not the list. Twenty new liens fit comfortably.

test_manyNewAdverseDocsFitInGasBudget
ATTACK 09
Outage

ACRIS answers with nothing.

Zero documents looks like a clean lot but is more likely an outage or a wrong BBL. The workflow refuses to report.

assertNonEmpty · vitest
ATTACK 10
Cut-off

A busy lot hits the 5,000-row limit.

A response at the limit may be missing a lien. The workflow fails static and writes nothing.

assertComplete · vitest
ATTACK 11
Old records

Pre-2003 IDs like FT_2300000813130.

They used to crash the conversion to on-chain IDs. They are now hashed instead.

legacy non-numeric ids · vitest
ATTACK 12
Split brain

Nodes see rows in a different order.

Queries are ordered by document ID and results are sorted and de-duplicated, so every node produces identical bytes.

same docs, same docSetHash · vitest

still open

What could still go wrong.

open-risks.fighonest

Open risks Known

  • The demo token trusts the simulator's placeholder owner, which is public. Anyone using the mock forwarder could report to it.
  • Every node reads the same API. If ACRIS itself is wrong, the token is wrong.
  • The issuer can clear a restriction. It is public and scoped, but it is a power.
  • Not audited. A hackathon build.

Production fix Planned

  • Point the token at a deployed workflow's owner with setExpectedWorkflowOwner.
  • Use Chainlink's production forwarder instead of the mock one.
  • Add a second data source so nodes compare two records.
  • Have the issuer be a real multisig, not a single wallet.
